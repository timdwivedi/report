     - Type a filename → it finds the file instantly

## SO-37B: War Stories — chain.sh Failures & Hard Lessons
**Duration**: 20-25 min

**COLD OPEN**
> "Before you run your first chain.sh build, I need to tell you about every time this system broke. Not to scare you. Because every one of these failures taught me something that made the system better — and if I tell you now, you skip six months of pain.
>
> This is the video I wish someone made for me. Every disaster. Every stupid mistake. Every 'oh fuck' moment. And what we changed so it never happens again."

**MAIN CONTENT**

1. **The Delete Everything Incident (The Big One)**
   - "This is the one that almost ended me."
   - "The build pipeline creates a project folder from the company name. Company name becomes a folder name. Simple."
   - "Except one client submission had an EMPTY company name field. No name. Blank."
   - "The system tried to create a folder from a blank name. It ended up pointing at the PARENT folder — the one that contains ALL client builds."
   - "Then the cleanup step said 'delete this folder and start fresh.'"
   - "It deleted EVERY client build. Every project. Every folder. Gone. Permanently."
   - "No confirmation. No undo. No recovery. Months of work wiped in 2 seconds."
   - "The fix was simple: before deleting ANYTHING, check that the folder name isn't empty and isn't a parent folder. Two safety checks that would have saved everything."
   - "We also added a rule: always LOCK the folder path yourself with the `--output` flag. Don't let the system generate folder names from database data. YOU decide the path."
   - **Rule:** "Never let automation delete things without safety checks. And always specify exactly where things go — don't trust auto-generated names."

2. **The Empty Field Trap**
   - "Related to the above. The company name came from a database lookup."
   - "The system had a fallback: 'if company name is missing, use a default.' But the company name wasn't MISSING — it was EMPTY. Blank. There's a technical difference."
   - "The fallback didn't trigger because the field existed — it just had nothing in it."
   - "We thought we had a safety net. We didn't."
   - "Fix: don't just check if a field exists. Check if it actually has content. 'Exists' and 'has something useful' are two different things."
   - **Rule:** "Empty fields are invisible killers. Always verify the data has ACTUAL content, not just that the field exists."

3. **The Process Drift Problem**
   - "This one bit us repeatedly and it's the most common mistake operators will make."
   - "Remember how each department has two versions — one for the automated pipeline, one for when you're working in the workspace? They started identical."
   - "Then I updated the workspace version with a new quality check. Forgot to update the automated one."
   - "Then I updated the automated version with a new feature. Forgot to update the workspace one."
   - "After two months: the two versions were running completely different processes. One produced different results than the other. Nobody knew which version was 'right.'"
   - "It's like if your sales team has an email sequence in Mailchimp AND a copy in a Google Doc. Someone updates one, forgets the other. Now half the team is sending version A and the other half is sending version B."
   - "The fix: ONE master version. Everything else reads from it. And we built a tool that detects when the versions have drifted apart — run it after any update."
   - **Rule:** "ONE source of truth. If the same process lives in two places, they WILL diverge. Guaranteed."

4. **The Find-and-Replace Massacre**
   - "We had a tool that renames a client folder and updates all references in all files."
   - "It did a simple find-and-replace: find the old name, replace with the new name."
   - "The client's short name was 'dg'. Two letters."
   - "The tool replaced every 'dg' in every file. Including INSIDE words."
   - "'budgeting' became 'bunewnameting'. 'knowledge' became 'knowlenewnameledge'. 'edging' became 'enewnaming'."
   - "Corrupted dozens of files. All the content was destroyed."
   - "It's like doing find-and-replace in a Word doc for 'an' and accidentally turning 'annual' into 'NEW-annual' and 'plan' into 'plNEW'."
   - "Fix: the system now only replaces the name when it appears in the right context — inside folder paths and URLs — not inside words."
   - **Rule:** "Find-and-replace is a weapon. Short names are dangerous. Always make sure you're only replacing what you intend to replace."

5. **The Silent Overwrite**
