## Lessons Learned

1. **Type file editing needs extra care.** When `app.ts` has repeated patterns (e.g., `}` after similar fields), always provide 3+ lines of unique surrounding context. Prefer adding new types at the END of the file.

2. **Column width rebalancing is easy to miss.** When adding a new column to DataTable, all existing column widths need adjustment. This should be a checklist item.

3. **Contract vs all-in distinction must be front-of-mind.** Every feature that touches quantities or pricing needs to ask: "does this apply to contract products, all-in products, or both?" The smart split only applies to contract. The CSV import handles both.

4. **Git strategy should be decided upfront.** Before starting any squad run, agree: commit on branch then merge? Or commit directly to main? This avoids mid-session confusion.

5. **The Provocateur phase is high-value.** The 7 elite features came from creative review after R1 passed. This should be formalized — now it is (PB-7 agent added to post-build.sh).

6. **BUILD_CONTEXT.md would have saved ramp-up time.** Each session had to re-read intel files to remember the industry, terminology, and business logic. Now that BUILD_CONTEXT.md exists, future sessions can ramp up in seconds.
