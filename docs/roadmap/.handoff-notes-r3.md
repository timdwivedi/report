## Watch-Outs (Things That Can Go Wrong)

### 1. Quoting Tier Extension (A1) -- Most Lines of Code
The current `quoting.ts` has 5 tiers for blank costs, screen print, and embroidery. All must be extended to 7 tiers with interpolated values. Watch for:
- The tier arrays use `min`/`max` ranges. Make sure there are no gaps or overlaps between adjacent tiers.
- The `getBlankCost()` and `getDecorationCost()` functions use `.find()` to locate the matching tier. If a quantity falls between tiers (e.g., exactly 35), the function must match correctly.
- The PricingGrid uses `midpoint` for lookups. Make sure midpoints are within the `min`/`max` of each tier.

### 2. ProductionTime Type Change (A3) -- Will Break Build Temporarily
Changing `ProductionTime` from a 5-value union to a 2-value union will cause TypeScript errors everywhere the old values are used. The primary location is `demo-data-provider.ts` but there may be others. Do a project-wide search for the old string literals before changing the type:
```
grep -r "'5-7 days'" --include="*.ts" --include="*.tsx"
grep -r "'7-10 days'" --include="*.ts" --include="*.tsx"
grep -r "'10-14 days'" --include="*.ts" --include="*.tsx"
grep -r "'15-20 days'" --include="*.ts" --include="*.tsx"
```

### 3. CreativeRequestDetailPanel (B1) -- Follow the ProductDetailPanel Pattern Exactly
The ProductDetailPanel is the reference implementation for nested slide panels. It uses:
- `Portal` from `@/components/shared/Portal`
- `AnimatePresence` from `motion/react`
- Fixed positioning with `z-[9999]`
- Backdrop with `bg-black/30 backdrop-blur-[2px]`
- Spring animation: `damping: 32, stiffness: 320`

Do NOT deviate from this pattern. Trevor expects visual consistency between all slide panels.

### 4. PricingGrid Responsive Fit (B3) -- Test at 60vw on 1440px
The ProductDetailPanel is 60vw. At 1440px viewport, that is 864px. With 7 columns at 80px + label column at 96px = 656px minimum. This should fit, but test it. If the margin input cells are too wide, the grid will overflow. The `overflow-x-auto` wrapper is the safety net but horizontal scroll is a bad experience.

### 5. Demo Data Consistency (C3) -- Cross-Reference IDs
The demo data provider uses hardcoded IDs for cross-referencing (e.g., `project.client_id` matches `client.id`). When adding new creative request versions or edit requests, make sure the IDs are unique and the parent references are correct. The demo data provider is ~2000 lines and easy to break with inconsistent IDs.

### 6. pricing_override in Save Handler (C1)
The `ProductDetailPanel.handleSave` callback builds an `updatedLineItem` object. The new `pricing_override` field must be included in this object. If it is forgotten, the override will be lost when the user saves. Check that `onSave` propagates the value.
