### Naming Conventions

- Add-on IDs: `ao-{project}-{lineItem}-{sequence}` (e.g., `ao-1-3-2`)
- Decoration location IDs: `dloc-{product}-{sequence}` (e.g., `dloc-1-3`)
- Product IDs: `prod-{number}` (established pattern)

### Key Warnings

1. **`LineItemAddOn` now requires `id` field** — When creating new add-ons in UI, use `Date.now()` pattern: `id: \`ao-${Date.now()}\``
2. **`sale_price_per_unit` is required** — This is the customer-facing price (markup over cost). Default to `0` when user hasn't set it yet.
3. **`quantities_received` is required on `ProjectLineItem`** — Always initialize to `false` when creating new line items.
4. **`level` field on add-ons** — `'product'` = applies to whole item (Folding, Gift Box). `'location'` = tied to specific decoration (Puff Ink, Metallic Ink). Location-level must also set `decoration_id`.
5. **Quoting backward compat** — Old add-ons without `level` are treated as product-level. No migration needed.
6. **`decoration_locations` on Product is optional** — Only 3 demo products have it. The Tailor should handle `undefined` gracefully in the ProductEditModal decorations tab.
7. **`ProductColor.images` is optional** — Only a few demo colors have images. The Tailor should show a placeholder when no images exist.
8. **API scraper route returns different mocks based on URL** — The Tailor's `ProductScrapeReview.tsx` should call `POST /api/products/scrape` with `{ url }` and render the returned `ScrapedProductData`.
