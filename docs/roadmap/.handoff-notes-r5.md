## Naming Conventions

### IDs
- Add-on IDs: `ao-{project}-{lineItem}-{sequence}` (e.g., `ao-1-3-2`)
- Ticket IDs: `TKT-2026-XXXX` format
- Project IDs: plain numbers as strings: `'1'`, `'2'` (NOT `'proj-1'`)
- Shipment IDs: `ship-{orderId}-{sequence}`
- Split shipment destination IDs: `dest-{Date.now()}-{sequence}`

### Price Codes
- Always uppercase single letter: `'A'` through `'R'`
- Net cost = `listPrice * (1 - PRICE_CODE_DISCOUNTS[code])`
- Stored on `AllInPriceBreak` objects in `Product.all_in_price_breaks`

### Contact Types
- Stored as `ContactType`: `'order' | 'finance' | 'shipping' | 'billing' | 'general' | 'other'`
- Labels via `CONTACT_TYPE_LABELS` constant

## Key Warnings

1. **`project_deadline` field name** — The old name `enhanced_date` no longer exists anywhere. Any new code referencing dates must use `project_deadline`.
2. **`'entered'` order status removed** — The `OrderStatus` type no longer includes `'entered'`. Use `'order-entry-needed'` → `'in-production'` as first transition.
3. **`'partially-shipped'` is automatic** — Status transitions to `partially-shipped` when first shipment is added but not all items shipped.
4. **Split Shipment quantity validation** — Column totals MUST equal product total quantity. The builder enforces this before save.
5. **Price break net cost is computed** — `AllInPriceBreak.net_cost` should always equal `list_price * (1 - discount)`. Never set it manually.
6. **Portal two-phase flow** — `approval_phase` field controls portal rendering: `'collecting'` → `'final-approval'` → `'approved'`. Don't skip phases.
7. **Readiness gates** — Both `art_received` AND `quantities_received` must be true before financial calculations are presented to clients.
8. **Portal file linking** — Client-uploaded files can reference `product_id` and `decoration_location_id`. Cross-linked files store additional product IDs in `cross_linked_product_ids`.
9. **Public routes** — Two new public routes exist: `/ticket/[shareableLink]` (vendor ticket view) and `/creative/[shareableLink]` (creative team view). Neither requires auth.
10. **Multi-supplier pricing** — `Product.suppliers` is an optional array of `SupplierPricing`. When adding product to project, user should select which supplier's costs to use.
